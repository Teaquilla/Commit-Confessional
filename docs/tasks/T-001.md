## 5. Persyaratan

### 5.1 Struktur Data & Parser Terpadu (Dapat Dipakai Ulang oleh T-002)
Modul harus mengekspor struktur parsing:
```typescript
export interface ParsedCommit {
  hash: string;
  message: string;
  files: string[];
}

export interface ParsedInput {
  commits: ParsedCommit[];
  files: string[]; // Daftar nama file unik dari diff header (diff --git, +++ b/, --- a/)
  addedLines: string[]; // Baris penambahan kode (tidak termasuk header +++)
  deletedLines: string[]; // Baris penghapusan kode (tidak termasuk header ---)
  totalChanged: number; // addedLines.length + deletedLines.length
  hasDiff: boolean;
  hasCommits: boolean;
  hasCommitFiles: boolean; // Bernilai true jika ada berkas terasosiasi per commit (git log -p, --stat, --name-only)
}

export interface SignalResult {
  points: number;
  evidence: string;
  available: boolean;
}

export interface BaseScoreSignals {
  rushedCommits: SignalResult;
  shoutingMashing: SignalResult;
  repeatedFiles: SignalResult;
  debugLeftovers: SignalResult;
  diffSize: SignalResult;
  baseScore: number;
  dominantSignalReason: string;
}

export type SeverityBand = "MINOR" | "MODERATE" | "MAJOR" | "CRITICAL";

export interface PanicScoreResult {
  valid: boolean;
  errorMessage?: string;
  baseScore: number;
  finalScore: number;
  severity: SeverityBand;
  dominantReason: string;
  signals: BaseScoreSignals;
  parsed: ParsedInput;
}
```

### 5.2 Deteksi Input Tak Masuk Akal (Nonsensical Input)
Input ditolak sebelum parsing jika:
- Panjang karakter `< 20`, ATAU
- Tidak memuat satu pun penanda spesifik berikut:
  - `"diff --git "`
  - Pola hunk header: `/@@ -\d+(?:,\d+)? \+\d+(?:,\d+)? @@/`
  - `"+++ b/"`
  - `"--- a/"`
  - Pola commit log bawaan: `/commit [a-f0-9]{7,40}/`
  - Pola oneline log: `/^[a-f0-9]{7,40} .+/m`
*(Catatan: Jangan gunakan "---" saja sebagai penanda agar tidak terjadi false positive pada teks markdown/garis pemisah biasa).*
Jika ditolak, kembalikan `valid: false` dengan pesan spesifikasi:
*"That doesn't look like commits or code changes. Paste a git diff or commit messages and try again."*

### 5.3 Aturan Parsing Format Git
Mendukung 4 format masukan:
1. **Git Log Bawaan:** Blok `commit <hash>` diikuti metadata dan pesan terindentasi.
2. **Git Oneline:** Baris berpola `<hash-7-40> <message>`.
3. **Git Show / Git Log -p:** Kombinasi blok commit log dan baris diff/perubahan berkas.
4. **Unified Diff Murni:** Baris `diff --git`, `--- a/...`, `+++ b/...`, `@@ ... @@`, `+...`, `-...`.

### 5.4 Definisi Eksplisit 5 Sinyal Deterministik
1. **Sinyal 1: Rushed Commit Messages (Maks 30 Poin)**
   - Ketersediaan: Tersedia hanya jika `hasCommits` bernilai `true`. Jika tidak: `available: false`, `evidence: "Not available (no commit messages)"`.
   - Definisi low-effort: Pesan (lowercase, trim) cocok dengan salah satu dari daftar kata tetap:
     `{"fix", "fixed", "fix again", "wip", "test", "tests", "asdf", "asdfgh", "try again", "???"}`,
     ATAU pesan hanya terdiri dari satu kata, ATAU duplikat dari pesan commit sebelumnya (terhitung mulai kemunculan kedua).
   - Perhitungan poin: `Math.round((low_effort_count / total_commits) * 30)`.
   - Evidence template: `"${low_effort_count} of ${total_commits} commit messages are low-effort"`.
2. **Sinyal 2: Shouting or Keyboard Mashing (Maks 10 Poin)**
   - Ketersediaan: Tersedia hanya jika `hasCommits` bernilai `true`. Jika tidak: `available: false`, `evidence: "Not available (no commit messages)"`.
   - Shouting: Ada kata berhuruf besar semua minimal 4 huruf (`/\b[A-Z]{4,}\b/`), ATAU tanda seru/tanya berulang minimal 3 kali (`/[!?]{3,}/`).
   - Mashing: Karakter sama berulang 5 kali berturut-turut atau lebih (`/(.)\1{4,}/`).
   - Perhitungan poin: Jika terdeteksi = 10 poin; jika tidak = 0 poin.
   - Evidence template: Jika ada: `"Detected shouting or character mashing: ${snippet}"`; jika tidak: `"No shouting or character mashing detected"`.
3. **Sinyal 3: Repeated File Touches (Maks 20 Poin)**
   - Ketersediaan: Tersedia HANYA jika `hasCommitFiles` bernilai `true` (ada informasi berkas per commit dari `git log -p`, `--stat`, `--name-only`). Jika tidak: `available: false`, `evidence: "Not available (no per-commit file history)"`.
   - Perhitungan poin: Jika ada berkas disentuh di $\ge 3$ commit = 20 poin; jika di 2 commit = 10 poin; jika di $\le 1$ commit = 0 poin.
   - Evidence template: Jika ada churn: `"${churnFile} modified across ${churnCount} commits"`; jika tidak: `"Files modified across at most ${maxCount} commits"`.
4. **Sinyal 4: Debug Leftovers (Maks 20 Poin)**
   - Ketersediaan: Tersedia HANYA jika `hasDiff` bernilai `true`. Jika tidak: `available: false`, `evidence: "Not available (no diff lines)"`.
   - Definisi: Baris penambahan (`addedLines`) yang memuat kata kunci: `\b(console\.log|print\(|debugger|var_dump)\b`.
   - Header `+++` dan `---` BUKAN baris penambahan dan TIDAK BOLEH dihitung.
   - Perhitungan poin: `Math.min(5, debug_count) * 4`.
   - Evidence template: `"${debug_count} debug statements found in added lines"`.
5. **Sinyal 5: Diff Size (Maks 20 Poin)**
   - Ketersediaan: Tersedia HANYA jika `hasDiff` bernilai `true`. Jika tidak: `available: false`, `evidence: "Not available (no diff lines)"`.
   - Definisi: `totalChanged` = baris ditambah (`addedLines.length`) + baris dihapus (`deletedLines.length`). Header `+++` dan `---` tidak dihitung.
   - Perhitungan poin: `> 300` baris = 20 poin; `100–300` baris = 10 poin; `< 100` baris = 0 poin.
   - Evidence template: `"${totalChanged} total lines changed in diff"`.

### 5.5 Normalisasi Umum & Severity Bands
- **Normalisasi Umum:**
  `maxAvailablePoints` = penjumlahan poin maksimum dari seluruh sinyal yang berstatus `available: true`.
  Jika `maxAvailablePoints === 0`, `baseScore = 0`.
  Jika `maxAvailablePoints > 0`, `baseScore = Math.min(100, Math.max(0, Math.round((totalEarnedPoints * 100) / maxAvailablePoints)))`.
- **Severity Bands:**
  - `MINOR`: 0 – 24
  - `MODERATE`: 25 – 49
  - `MAJOR`: 50 – 74
  - `CRITICAL`: 75 – 100
- **Dominant Signal Reason:**
  Ditentukan dari sinyal `available: true` yang memiliki poin absolut tertinggi. Jika seri, ambil urutan sinyal terendah (1 $\rightarrow$ 2 $\rightarrow$ 3 $\rightarrow$ 4 $\rightarrow$ 5).
  Templat kalimat tetap per sinyal (Bahasa Inggris):
  - Sinyal 1: `"Frequent low-effort commit messages indicate rushed progression."`
  - Sinyal 2: `"Aggressive punctuation or shouting indicates elevated developer stress."`
  - Sinyal 3: `"Repeated modifications to the same files signal persistent churn."`
  - Sinyal 4: `"Leftover debugging statements indicate uncleaned work."`
  - Sinyal 5: `"Large changeset volume increases risk and review complexity."`
  - Jika seluruh poin sinyal 0: `"No significant panic signals detected in changeset."`

## 7. Batasan & Invarian
- **Batasan:** Modul mandiri tanpa import dari modul lain (`src/lib/panic-score.ts`); hindari enum dan namespace (gunakan union type `type SeverityBand = ...` karena Node hanya menghapus anotasi tipe); tanpa dependensi baru.
- **Invarian yang Wajib Terjaga:**
  1. Input pengguna tidak pernah disimpan ke disk atau log server.
  2. Nilai `baseScore` dan `finalScore` selalu integer berada dalam batas [0, 100].
  3. Parsing regex harus linear/deterministik tanpa catastrophic backtracking pada input besar.

---

## 8. Penanganan Kasus Tepi (Edge Cases)
- **Input Tak Masuk Akal / Kurang dari 20 Karakter:** Mengembalikan objek `valid: false` dengan pesan spesifikasi PRD.
- **Input Diff Sangat Besar (50.000 karakter):** Selesai dalam waktu singkat (<100ms) tanpa regex freezing.
- **Singular Acronym ("WIP", "API"):** Tidak memicu shouting signal karena panjang huruf < 4.
- **Header Diff ("+++", "---"):** Dieliminasi dari penghitungan diff size dan debug keywords.
